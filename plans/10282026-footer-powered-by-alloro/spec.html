Why

On 2026-07-01 the "Website Powered by Alloro" credit was pasted into each live site's saved footer by hand. Regenerated sites lost it: on 2026-10-28, 10 of 18 live sites in production had no credit. Dave asked for it on every site.

What

The renderer adds the credit to the footer of every rendered page, at serve time. A regenerate can no longer remove it. Sites that already carry a credit in their saved HTML are left alone, so no page shows two. getalloro.com's own project is excluded (Dave, 2026-10-28).

Execution worktree: /Users/rustinedave/Desktop/website-builder-rebuild-worktrees/footer-powered-by-alloro, branch codex/footer-powered-by-alloro, from origin/main at a7d5aca. Approach chosen by Dave (renderer injection over pasting into saved footers).

Context

  • src/utils/renderer.ts renderPage() - assembles header + sections + footer for both page and post routes; the one place to add the credit.
  • Credit markup matches the existing block on 1endodontics.com and garrisonorthodontics.com (logo + "Website Powered by Alloro", link to getalloro.com), with inline styles and color: inherit so it reads on light and dark footers.

Reference file: src/utils/review-read-more.ts - small, documented single-purpose util that renderer.ts-level code calls.

Risk

Level: 2 - visible change on every live client site at once.

  • Credit placed inside a footer whose root is a flex row could sit beside the columns. Mitigation: the block is width:100% and goes before the last </footer>; a footer with no <footer> tag gets it appended after its HTML.
  • Duplicate credit on sites that already have one. Mitigation: skip when the assembled page already contains "Powered by … Alloro" (the Alloro Protect form badge is never in saved HTML; it is stripped and added by script).
  • Render cache (Redis) keeps serving old HTML after deploy. Mitigation: note in PR; cache entries expire on their own.

Blast radius: every page and post rendered by renderPage() (src/routes/site.ts page and post routes). Artifact pages and system pages (404, success, archived) are untouched.
